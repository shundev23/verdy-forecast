## 1. この文書について

- 東京ヴェルディの次の試合を分析する個人用Webアプリ「verdy-forecast」を、VS Code の Claude Code で作るための手順書。
- 作業は Phase 0〜9 に分けて、さらに番号付きのステップ（例: 2-3）に分けてある。Claude Code には1ステップずつ渡す。
- 「要決定」と書いてあるものは、そのステップに入る前に壁打ちで決める。決めたら、この文書の該当箇所を更新する。
- 各ステップの「完了条件」をすべて満たしたら、次に進む。

### Azure を操作するときのルール

- Azure を変更するのは「自分（ポータルか Azure CLI）」と「承認したあとのパイプライン」だけ。Claude Code には Azure を操作させない。
- Azure CLI は自分が使うときだけログインして、使い終わったら `az logout` する。ログインしたままにしておくと、同じ PC で動く Claude Code からも使えてしまうため。
- Claude Code の権限ルール（`.claude/settings.json`、付録 B）で、`az` などのコマンドと、ログイン情報や秘密情報の保存場所の読み取りを禁止する。ただし、このルールはコマンドの文字列で判定するだけなので、上の2つの運用とセットで使う。
- ローカルの開発とテストでは Azure のサービスに接続しない（SQL と Storage は Docker、AI Language は偽物の実装）。

### 5.1 決まったこと

#### D4: Elo の設定（2-1 で決定、2026-11-24）

| 項目 | 決めたこと |
|---|---|
| 対象の試合 | J1 の全試合（リーグ戦だけ。カップ戦や ACL は使わない）。2026年前半の百年構想リーグも含める |
| 初期値と始める時点 | 全チーム 1500 で、使えるいちばん古いシーズンから計算を始める。最初の1シーズンは慣らしとして、評価に使わない |
| 得点差の補正 | K に掛ける。1点差以下は ×1、2点差は ×1.5、3点差以上は ×(11 + 点差) ÷ 8 |
| K 値 | 候補 10、15、20、25、30、40 から、ウォークフォワードの平均 RPS が最小のものを選ぶ。既定値は 20 |
| ホームの補正 | 候補 0、25、50、75、100 から、K と一緒に選ぶ。既定値は 50。Elo を更新するときの期待値の計算にだけ使う |
| シーズンの区切りでの引き戻し | R ← 平均 + c ×（R − 平均）。c は 0.6、0.7、0.8、0.9、1.0 から、K と一緒に選ぶ。既定値は 0.8。百年構想リーグと 2026-27 の開幕も、シーズンの区切りとして扱う |
| 昇格チームの初期値 | 前のシーズンの下位3チームの最終値の平均 |
| PK で決着した試合 | 90分のスコア（引き分け）として扱う |

- K、ホームの補正、c の実際の値は、過去のデータが手元にそろった時点（Phase 4 以降）に `analysis/` で選んで、評価の記録に残す。選んだ値は、モデルのバージョンとして DB に保存する（分析の出力なので、リポジトリには入れない）。

#### D5: Elo の差から期待得点に直す方法（2-1 で決定、2026-11-24）

- ポアソン回帰を使う。log λ(ホーム) = a(ホーム) + b × Δ、log λ(アウェイ) = a(アウェイ) − b × Δ。Δ は（ホームの Elo − アウェイの Elo）÷ 100 で、試合前の値を使う。ホームの有利さは、a(ホーム) と a(アウェイ) の差に入る。
- 係数（a(ホーム)、a(アウェイ)、b）は、最尤法（ニュートン法）で推定する。推定は Domain に C# で実装して、本番と検証で同じ計算を使う。
- 係数を推定し直すのはシーズンの区切りだけで、前のシーズンまでのデータだけを使う（データリーケージの防止）。
- スコアの分布は各チーム0〜10点で計算して、合計が1になるように割り戻す。勝ち・分け・負けの確率と予想スコアの上位は、この分布から出す。
- テストでは、決まった係数から作ったデータ（シードは固定）を使って、元の係数を推定し直せることを確かめる。
- 引き分けの補正（Dixon–Coles）は v1 では入れない。評価手順書 9.5 の確率の当たり具合で引き分けがずれていたら、v2 で検討する。

#### D6: 採点（2-1 で決定、2026-11-24）

- 範囲と刻みは 1.0〜10.0 の 0.5 刻み。6.0 が及第点。
- 出場15分未満の選手は採点しない（「－」）。自分で付けることはできる。
- 参考点（採点の下書き）は、次の足し引きで出す。使うのは、公式サイトを見て手で入れる数字だけ。足し引きがすべて 0.5 の倍数なので、丸めは要らない。

| 項目 | 点 |
|---|---|
| 基本 | 6.0 |
| 得点 | 1点ごとに +1.0 |
| アシスト | 1本ごとに +0.5 |
| チームの勝ち、負け | +0.5、−0.5 |
| 無失点（GK と DF、60分以上の出場） | +0.5 |
| チームが3失点以上（GK と DF） | −0.5 |
| 退場、オウンゴール | それぞれ −1.0 |
| 範囲 | 4.0〜9.0 に収める |

- 最終点は自分が付ける。参考点と最終点の両方を保存する。

#### D7: MVP（2-1 で決定、2026-11-24）

- 候補は、採点のある選手だけ。最終点がいちばん高い選手を MVP にする。
- 同点のときは、得点 → アシスト → 出場時間 → 背番号の小さい順で比べる（必ず1人に決まる）。
- 採点が0件なら、MVP はなし。
- 手で変えた MVP は、あとで採点を直しても自動で上書きしない。

#### D8: ％を入れなかった予想を確率に直すルール（2-1 で決定、2026-11-24）

| 選んだ結果 | 勝ち | 引き分け | 負け |
|---|---|---|---|
| 勝ち | 60% | 25% | 15% |
| 引き分け | 20% | 60% | 20% |
| 負け | 15% | 25% | 60% |

- 結果の順番（勝ち＞引き分け＞負け）を考えて、選んだ結果の隣に多く配る。どの結果にも 0% を付けない（対数損失が無限大にならないように）。
- 評価に使う確率（％を入れたときはその値、入れていないときは上の表の値）は、予想を保存するたびに、出どころ（入れた値か、ルール v1 で直した値か）と一緒に保存する。キックオフ以降は変更できないので、キックオフの時点の値がそのまま残り、あとでルールを変えても過去の評価は変わらない（2-3 で決定。ロックの瞬間に動く処理は作らない）。
- ％を入れるときの条件: 3つとも入れて合計100%、どれも1%以上、選んだ結果の％がいちばん高い（同じ値は可）。3-3 で検証する。
- 3択と予想スコアが食い違う入力（勝ちを選んで 1-1 にするなど）は拒否する。3-3 で検証する。

## 付録 B: Claude Code の権限ルール（`.claude/settings.json`）

リポジトリにコミットして使う。`deny` は禁止、`ask` は毎回確認が出る。

```json
{
  "permissions": {
    "deny": [
      "Bash(az *)",
      "PowerShell(az *)",
      "Bash(azd *)",
      "PowerShell(azd *)",
      "Bash(func azure *)",
      "PowerShell(func azure *)",
      "PowerShell(Connect-AzAccount *)",
      "Bash(dotnet user-secrets *)",
      "PowerShell(dotnet user-secrets *)",
      "Read(~/.azure/**)",
      "Read(~/AppData/Roaming/Microsoft/UserSecrets/**)"
    ],
    "ask": [
      "Bash(git commit *)",
      "PowerShell(git commit *)",
      "Bash(git push *)",
      "PowerShell(git push *)"
    ],
    "disableBypassPermissionsMode": "disable"
  }
}
```

- `az`、`azd`、`func azure`、`Connect-AzAccount`: Claude Code から Azure を操作させない。
- `dotnet user-secrets`: 秘密情報の一覧表示や書き換えをさせない（値は自分で入れる）。
- `~/.azure` と `UserSecrets` の読み取り: Azure CLI のログイン情報と、ローカルの秘密情報を読ませない。
- `git commit` と `git push`: 実行する前に毎回確認する。
- `disableBypassPermissionsMode`: 確認をすべて飛ばすモードを使えないようにする。
- このルールはコマンドの文字列で判定するだけなので、`sh -c` のような別の書き方では止まらないことがある。だから「Azure CLI にログインしたままにしない」「Azure の変更はパイプラインの承認を通す」とセットで使う。
